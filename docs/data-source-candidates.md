## 🏆 M-A0085-001（驗證程度最高）

**健康氣象－熱指數及警示全台各鄉鎮五日逐三小時預報**

狀態：🏆 已實際打過 API、看過真實回應本體確認 schema——是本文件唯一一個不只看
技術文件、有真實資料佐證的候選

### 指數說明

WBGT（Wet-Bulb Globe Temperature，綜合溫度熱指數）：同時考量溫度、相對濕度、太陽
輻射、風速的健康效應指數，跟熱傷害急診/就診人數相關性很強。官方四級警示：

| WBGT 小時最高值 | 警示等級 |
|---|---|
| ≥32（或連續3天≥32的下一階） | 注意 cautious |
| ≥34（或連續3天≥32） | 警戒 alert |
| ≥36（或連續3天≥34） | 危險 dangerous |
| ≥38（或連續3天≥36） | 高危險 high dangerous |

### 實測 JSON 結構（已用嘉義縣資料驗證）

```json
{
  "records": {
    "Locations": [
      {
        "CountyName": "嘉義縣",
        "Location": [
          {
            "TownName": "新港鄉",
            "Geocode": "10010070",
            "Latitude": "23.55380058",
            "Longitude": "120.33899690",
            "Time": [
              {
                "IssueTime": "2026-08-05 09:00:00",
                "WeatherElements": { "HeatInjuryIndex": 32, "HeatInjuryWarning": "注意" }
              }
              // ...5天、逐3小時，共約40筆，未達門檻時 HeatInjuryWarning 是空字串 ""
            ]
          }
          // 同縣市其他鄉鎮（例如「東石鄉」）也在同一份回應裡
        ]
      }
      // 其他縣市（例如雲林縣）
    ]
  }
}
```

**關鍵確認**：`TownName` 直接是「新港鄉」這種跟 `DIRECTION_TOWNS` 完全一致的鄉鎮名稱，
不用做任何座標比對或名稱轉換；時間粒度（逐3小時、5天）比現有 F-D0047 更長，跟現有
降雨資料的3小時分格天然對齊。

**潛力**：現在的 Comfort Preference Layer v2 體感軸是從 `WeatherDescription` 文字關鍵字
猜測（悶熱/高溫/舒適），本質是啟發式判斷。M-A0085-001 提供官方精確計算的數值 + 四級
警示，理論上比文字關鍵字判斷更準確、更有公信力。但目前 v2 已上線穩定，不需要現在就換，
先記錄這個可能性即可。

**待補**：打通的網址是 `api/v1/rest/datastore` 還是 `fileapi/v1/opendataapi` 兩種路徑
格式中的哪一個，目前未確認，之後真的要接入時需要補上。

> **修正說明**：原始筆記把 F-D0047-025 / -029 標成未使用的延伸資料，但這兩個其實

> -031 這兩個「未來1週」版本。

| 代碼 | 名稱 | 狀態 | 用途 |
|---|---|---|---|
| F-D0047-029 | 嘉義縣未來3天 | ✅ 已使用 | 驅動新港/溪口/民雄/朴子/大林的今日決策 |
| F-D0047-025 | 雲林縣未來3天 | ✅ 已使用 | 驅動北港/斗南的今日決策 |
| F-D0047-027 | 雲林縣未來1週 | 🟢 規格已確認 | Future Schedule Planning + UV 資料源 |
| F-D0047-031 | 嘉義縣未來1週 | 🟢 規格已確認 | Future Schedule Planning + UV 資料源 |

### 🎯 UV 資料源結論（取代 F-B0053 候選）

官方技術文件確認「未來 7 天逐 12 小時與逐日預報」格式（F-D0047-027 / -031 屬於此類）
的 15 個氣象因子裡包含 `UVIndex`（紫外線指數）跟 `UVExposureLevel`（紫外線曝曬級數）。
地點結構跟已上線的 -029 / -025 完全同源（`LocationName` 是鄉鎮名稱，附 Geocode/經緯度），
理論上涵蓋鄉鎮相同，只是預報天數從 3 天延伸到 7 天，更新頻率相同（每日
05:30/11:30/17:30/23:30）。

**結論**：F-B0053 系列（觀星/單車等育樂天氣預報）不再需要評估——UV 資料直接從已經在
用的 F-D0047 家族週預報變體就能拿到，地點是我們原本就要的七鄉鎮。

**尚未 100% 確認**（技術文件是規格說明，不是實際資料內容）：還沒有實際拉過
F-D0047-031/-027 的即時回應本體，確認 (1) 嘉義五鄉鎮/雲林兩鄉鎮是否真的都出現在
`LocationName` 清單裡 (2) `UVIndex`/`UVExposureLevel` 實際回傳的是有效數值。這兩點
之後真的要接入時才需要驗證。

### 分層歸類

```text
F-D0047-029 / F-D0047-025（✅ 已上線）→ Today Decision Engine（今天出門決策層，現況）

F-D0047-027 / F-D0047-031（🟢 已驗證有 UVIndex，未使用）
        ↓
Future Schedule Planning Layer（未來行程規劃層）＋ UV 資料源（一魚兩吃）
```

這組比 F-C0035 天氣分析圖更符合專案方向，因為它仍然是「鄉鎮級、生活語言、直接可用」，
不是「氣象圖表」。未來如果要做「這週哪天適合帶小孩出去」，-027 / -031 會比地面天氣圖、
最新天氣圖更有價值，優先度應該高於 F-C0032 / F-C0035 系列。
