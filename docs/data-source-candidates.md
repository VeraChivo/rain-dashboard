## 🏆 M-A0085-001 詳細記錄

**健康氣象－熱指數及警示全台各鄉鎮五日逐三小時預報**

架構位置：**Comfort Preference Layer**（未來可能取代/強化體感軸）

本文件唯一一個不只看技術文件、有真實 API 回應佐證的候選。

### 指數說明

WBGT（Wet-Bulb Globe Temperature，綜合溫度熱指數）：同時考量溫度、相對濕度、太陽
輻射、風速的健康效應指數，跟熱傷害急診/就診人數相關性很強。官方四級警示：

| WBGT 小時最高值 | 警示等級 |
|---|---|
| ≥32（或連續3天≥32的下一階） | 注意 cautious |
| ≥34（或連續3天≥32） | 警戒 alert |
| ≥36（或連續3天≥34） | 危險 dangerous |
| ≥38（或連續3天≥36） | 高危險 high dangerous |

### 實測 JSON 結構（已用嘉義縣資料驗證）

```json
{
  "records": {
    "Locations": [
      {
        "CountyName": "嘉義縣",
        "Location": [
          {
            "TownName": "新港鄉",
            "Geocode": "10010070",
            "Latitude": "23.55380058",
            "Longitude": "120.33899690",
            "Time": [
              {
                "IssueTime": "2026-08-05 09:00:00",
                "WeatherElements": { "HeatInjuryIndex": 32, "HeatInjuryWarning": "注意" }
              }
              // ...5天、逐3小時，共約40筆，未達門檻時 HeatInjuryWarning 是空字串 ""
            ]
          }
          // 同縣市其他鄉鎮（例如「東石鄉」）也在同一份回應裡
        ]
      }
      // 其他縣市（例如雲林縣）
    ]
  }
}
```

**關鍵確認**：`TownName` 直接是「新港鄉」這種跟 `DIRECTION_TOWNS` 完全一致的鄉鎮名稱，
不用做任何座標比對或名稱轉換；時間粒度（逐3小時、5天）比現有 F-D0047 更長，跟現有
降雨資料的3小時分格天然對齊。

**潛力**：現有體感軸是文字關鍵字啟發式判斷，M-A0085-001 提供官方精確計算的數值 +
四級警示，理論上更準確、更有公信力。但目前 v2 已上線穩定，不需要現在就換。

**待補**：打通的網址是 `api/v1/rest/datastore` 還是 `fileapi/v1/opendataapi`，目前未
確認，之後真的要接入時需要補上。

## F-D0047-027 / F-D0047-031 詳細記錄

**鄉鎮天氣預報－單一鄉鎮市區預報資料－雲林縣/嘉義縣未來1週天氣預報**

架構位置：**Future Planning Layer**（主要用途）＋ **Comfort Preference Layer**（UV 資料源，附帶用途）

官方技術文件確認「未來 7 天逐 12 小時與逐日預報」格式的 15 個氣象因子裡包含
`UVIndex`（紫外線指數）跟 `UVExposureLevel`（紫外線曝曬級數）。地點結構跟已上線的
-029 / -025 完全同源（`LocationName` 是鄉鎮名稱，附 Geocode/經緯度），理論上涵蓋鄉鎮
相同，只是預報天數從 3 天延伸到 7 天，更新頻率相同（每日 05:30/11:30/17:30/23:30）。

**尚未 100% 確認**（技術文件是規格說明，不是實際資料內容）：還沒有實際拉過即時回應
本體，確認 (1) 嘉義五鄉鎮/雲林兩鄉鎮是否真的都出現在 `LocationName` 清單裡 (2)
`UVIndex`/`UVExposureLevel` 實際回傳的是有效數值。

架構位置：**Comfort Preference Layer 的附加補強**，不是取代——UV 的主要方案仍是

### F-B0053-067（🟢 已確認真實存在，schema 待驗證）

**育樂天氣預報－觀星一週24小時天氣預報**

存取路徑要用 `fileapi/v1/opendataapi/{id}?format=JSON`（舊式檔案 API，不是一般的
`api/v1/rest/datastore/{id}`）。地點是 72 個觀星景點檔案，不是行政鄉鎮——這代表它

家族的部分資料集，欄位不只活動描述，還包含 T（溫度）、RH（濕度）、MaxAT/MinAT

「今晚適不適合這類活動」，而不是「今天出門舒不舒服」。跟既有 Comfort Layer 是加法
關係：

```text

        ↓
Activity Comfort Enhancement（附加，非取代）
```

**待驗證**：F-B0053-067 API 實際查得到嗎、欄位格式如何、是否真的有 UVI/
